## 3. Exact optimizer semantics and source evidence

Use pinned torch2.5.1+cu121 `torch.optim.Adam`, `amsgrad=True`, LR.001, betas(.9,.999), eps1e-8. Preserve default `foreach=None`, `fused=None`, `capturable=False`, `differentiable=False`, `maximize=False`; do not introduce AdamW/decoupled decay or silently change backend dispatch. The existing source lets PyTorch select supported foreach execution; both installed single-tensor and foreach implementations implement the same coupled rule. Their numerical trajectories need not be bitwise identical to another dispatch.

For each minibatch, compute LE+Ls, backward, record task-gradient diagnostics, call the inherited `clip_grad_norm_(model.parameters(),5,error_if_nonfinite=True)`, then `optimizer.step()`. For each parameter with a gradient, let gbar be that **already clipped task gradient**, p the current parameter and lambda be0 or1e-4. Adam internally uses:

    gtilde = gbar + lambda*p
    m_t = beta1*m_(t-1) + (1-beta1)*gtilde
    v_t = beta2*v_(t-1) + (1-beta2)*gtilde^2
    vmax_t = max(vmax_(t-1),v_t)
    p_next = p - [lr/(1-beta1^t)] * m_t / [sqrt(vmax_t)/sqrt(1-beta2^t) + eps]

The term lambda*p is added **after** external clipping and enters both moments and AMSGrad's maximum. Clip5 bounds the task-gradient norm according to the inherited routine; it does not bound the total effective gtilde in the same way. This is not multiplicative AdamW shrinkage, not a second clip and not equivalent to inserting a norm penalty into LE+Ls before clipping. The derivative of lambda/2 times the parameter squared norm is lambda*p, but the implemented order is the equation above. No second implementation of the optimizer will be used for production.
