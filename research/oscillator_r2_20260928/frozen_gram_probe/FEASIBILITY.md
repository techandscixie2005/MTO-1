# Feasibility of a two-arm convex frozen-feature probe

**Status:** resource and shape audit only. No Gram extraction, regression fit, validation prediction, GPU job, or test access has run. This note supports a forthcoming fixed protocol and is not execution authorization.

## Inputs and feature geometry

The sealed frozen cache already contains state-conditioned hidden features `h` with shape `[120355,10,128]` for training and `[6686,10,128]` for validation, plus E, the FP32 base, the native FP64 base, raw printed f, masks, IDs and global indices. Its train and validation SHA-256 digests are `948f14528a222613cc3a590d3d8e710586374be28dc0826d43afde461de48b3b` and `f8f47fabcb00b0c03a99fa3d684a74294ff74fb0e9087f2301953802a6263848`. The cache manifest hash is `ca3eb18da9b2ee64677dbf989ead38a4f667f7663d2a7e7bad10eb2811bf3b11`. It has no tensor-channel output, so the frozen source must be forwarded once more to obtain those tensors. The previous GPU6 feature-cache pass took 48.1 seconds for train and 3.6 seconds for validation, before Gram work and disk writes.

The source `ReferenceStateCoupling` has `mto_channels=16`, hence 32 tensor channels of five `2e` components for each molecule/state: `T[N,10,32,5]`. The sealed decoder Cartesian basis has shape `[5,3,3]`. Its basis Gram differs from the identity by at most `7.28e-8` in FP64 after loading the FP32 checkpoint. That near-orthonormality is a useful sanity check, **not** permission to replace the specified Cartesian Gram with `T Tᵀ`.

For each state, promote both frozen T and the Cartesian basis to FP64, project `V[k,i,j] = Σ_m T[k,m] B[m,i,j]`, then form `G[k,l] = Σ_ij V[k,i,j] V[l,i,j]`. Retain the lexicographically ordered upper triangle `k≤l` (528 columns), multiplying off-diagonals by `√2` before train-only standardization. The common arm uses 128 h columns plus one native64 base-f column (129 slopes); the expanded arm appends 528 Gram columns (657 slopes). Each arm has one separate, unpenalized intercept: 130 and 658 coefficients respectively. Rows are individual state transitions, with every molecule contributing ten equally weighted rows. The train split has 1,203,550 rows; validation has 66,860.

The 657×657 FP64 covariance occupies 3,453,192 bytes (3.293 MiB), so both arms' sufficient statistics are small. A 640-row block of 657 FP64 features occupies 3.36 MB; the projected V and Gram intermediates also fit comfortably in a small bounded GPU/CPU batch. Keep h/base in the existing cache and Gram in separate server-only `.npy` memmaps; avoid a second complete row-matrix copy. This server currently reports 2.9 TB free disk and about 470 GiB available RAM. Even with temporary atomic output and page cache, the roughly 5.37 GB combined Gram files are well within capacity. The model plus a batch of T/V/G should fit an admitted A800 80GB GPU; reserve at least 8–12 GiB and check actual occupancy/health under the shared device lock before execution. The prior architecture run used GPU6 cleanly.

Computing the full expanded covariance has about `1,203,550 × 657² = 5.195×10¹¹` multiply-accumulate terms (roughly 1.04 TFLOP counting multiply and add). Two streaming passes over the train Gram suffice: a stable block-merged mean/variance pass, then an FP64 centered, standardized covariance and target cross-product pass. The common-arm covariance is exactly the leading 129×129 block of the same pooled statistics, with the same train means/standard deviations. Reusing the persistent train Gram avoids another expensive source-model forward for pass two and for train-fit metric replay. The existing validation h/base cache may be reused for alignment checks, but do not consume validation targets, construct validation Gram features, or make predictions until both train-only scalers and ridge coefficients are frozen and checksummed. Then generate the validation Gram once and predict both arms with that same feature cache. Nothing about validation outcomes changes the two fixed arms or their shared λ.

## Numerics and fixed solver

The proposed target is `r=(raw_f−base_native64)/f_std_train`. Estimate pooled train means and population variances using Chan/Welford block merge or an equivalently stable FP64 two-pass method. Remove columns whose train variance is exactly zero; apply no validation-derived scaling. Preserve column order and a zero-variance mask in the source manifest. After train centering/scaling, the intercept is the train residual mean. For nonconstant slopes solve `(ZᵀZ/N + 0.001 I) w = Zᵀ(r−mean(r))/N` by FP64 Cholesky. The ridge term makes the matrix strictly positive definite even if Gram columns are redundant. Require finite factors and a relative normal-equation residual ≤1e-10; cross-check both arms against an independent linear solve on the same sufficient statistics. This is one fixed coefficient value, not a hyperparameter search.

For both arms, predict `max(0, base_native64 + f_std_train × (mean(r)+Z w))`. Report the unprojected signed prediction and projection effect separately. Use the same exact frozen native64 base, raw-f truth, train-only scaling and nonnegative projection in both arms. Energy is frozen predicted E, never true E as an input. No state one-hot, new query, oracle feature, validation-based ridge choice, or test use is part of the probe.

Before an authorized run, the implementation should bind source/checkpoint/cache hashes, exact train/validation IDs and masks, the `[N,10,32,5]` tensor geometry and Cartesian basis, lexicographic Gram order, off-diagonal `√2`, and common-block identity. A fixed-batch uncached forward must reproduce cached h/E/base within the documented FP32 tolerance while the Gram source is read. Verify Gram symmetry and PSD on small rows, rotation/permutation invariance, nonnegative projection semantics, and full train/validation disjointness. Verify a streaming covariance against direct matrix statistics on a small **training-only** fixture; verify Cholesky and independent normal-equation residuals. Freeze both arm coefficients and preprocessing before any validation prediction. Require an independent code review and preflight PASS, healthy GPU admission with existing lock, and explicit coordinator authorization before fitting. Keep all Gram memmaps, coefficient arrays and raw predictions on the server; archive only code, configs, lightweight metrics and provenance.
