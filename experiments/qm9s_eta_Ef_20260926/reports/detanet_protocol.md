# DetaNet E/f 对照：证据、缺项与已批准执行方案

## 已核实的公开事实

- 官方源码：[WeiHuQLU/DetaNet](https://github.com/WeiHuQLU/DetaNet/tree/4f92e643ab64651b91c4a1392cf389ddfd0d89f0)，固定提交 `4f92e643ab64651b91c4a1392cf389ddfd0d89f0`。
- 补充材料 Section 3 / Table 2 第一行是同时训练十个激发能与十个振子强度，表中 E/f R² 为 0.956/0.134。
- 正文 Training hyperparameters：128维、3层、l=1,2,3、5 Å cutoff、32个Bessel基；Adam与AMSGrad；普通分子属性batch=64、初始lr=1e-3；MSE；每50个“epochs”检验，loss不下降则学习率减半；loss降至1e-5或达到1,000,000个“epochs”停止。
- 官方 `DetaNet` 支持 `scalar_outsize`、分子求和和原生标量MLP。`metrics.l2loss` 为直接的逐元素MSE。
- 官方仓库公开了十态能量、十态跃迁偶极和240维展宽光谱的模型加载方法/权重，但没有找到Table 2第一行的联合E/f专用配置或训练脚本。
- 公开训练notebook明确以NPA电荷为例：文字写5e-4，实际调用是AdamW、lr=1e-5、20轮；训练代码以批次step打印“Epoch”。这不能确立联合E/f实验的训练设置。
- Code Ocean页面本次无法访问，因此不能声称已检查其中未能访问的文件。

## 关键未公开/不明确项

2. “epoch”指完整数据轮次还是优化器批次更新；每50次如何汇总验证loss、与何值比较以及具体降率阈值。
3. 联合E/f专用停止/最低学习率/best选择规则，以及初始化、随机种子等运行细节。

## 实际冻结配置

- 完整官方DetaNet，原生20维标量输出，前十维E/eV，后十维原始oscillator_strength；分子求和，无MTO、A、softplus、裁剪或物理约束。
- 官方无权重MSE作用于20维原始标签，seed=11，从头训练。
- Adam+AMSGrad，lr=1e-3，batch=64，weight_decay=0，FP32，AMP/TF32关闭。
- 按正文保留：验证间隔50、学习率减半、停止阈值1e-5、最大1,000,000。结合官方Trainer将批次step打印为Epoch，将正文“epochs”解释为优化器更新次数：每50次更新完整验证，最多1,000,000次更新，约532个全量数据轮次。此计数单位是有源码依据的执行解释，原文存在歧义，并非发现了作者专用配置。
- 停止阈值应用于前一个验证间隔的训练平均MSE和全量验证MSE，两者均≤1e-5时结束；否则训练至更新上限。双侧停止参考公开Trainer的逻辑，阈值取正文1e-5，不取电荷示例1e-8。聚合方式为明确补全，避免用单个偶然低loss批次触发停止。
- 正文未给出完整降率判据，参考MTO：ReduceLROnPlateau，patience=50次验证、relative threshold=1e-4、min_lr=1e-6；factor=0.5来自正文。patience单位在本轮DetaNet为验证次数，即连续约2500次更新，不能把它描述成MTO的50个全量epoch。
- best按全量验证原始E/f MSE选择（缺项参考MTO）。每50次更新记录训练/验证E与f MSE和共同光谱指标。
- 不采用MTO的最少200轮、最多1000轮或150轮无改善早停，以免覆盖正文已明确的停止条件。
- 保持原训练无梯度裁剪、无输出变换；只检测非有限loss/梯度并如实记录失败。梯度范数记录不参与更新。
- 原始E/f拼接、无定标的官方MSE是对未公开联合标签配置的最小补全，已获用户授权；不能声称证实作者当时没有做过标签定标。
- 这将标为“原版架构/联合E-f方法重建对照”。计数单位解释、降率判据、best和未公开的联合标签处理均明确披露，不称为Table 2分数的严格复现。

批准后只启动一组DetaNet；训练前的少量scratch更新仅用于验证恢复状态，随后丢弃，正式实验重新从seed=11构造模型。检查与实际训练均保留记录。

## 必要适配范围

复用冻结分子ID、分组划分、坐标、原子与半径图；用原始f和mask。缓存图使用官方forward的edge_index接口。允许把elec/mass常量注册为非持久buffer以支持device/dtype迁移；不改forward算法、输出算子、可训练参数或初始化。环境沿用已验证的e3nn 0.4.4/PyTorch 2.5.1+cu121。

数据版本与90/5/5分组划分属于本轮协议，与论文数据和示例95/5划分不同。
