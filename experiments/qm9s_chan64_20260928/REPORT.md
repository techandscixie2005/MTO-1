## 1. 目的与假设

前序 c=16 的加权 trace 实验里，f 的 R² 长期卡在 0.35–0.42，而 train loss 持续下降。
提出的假设是：

> **MTO 把通道数从 128 降到 16，可能是 A（跃迁偶极张量）表达不准的原因。**

据此设计本消融：把通道数恢复（本次取 c=64），其余一切不变，看 f R² 是否上升。

## 2. 实验设置

**唯一变量**：`mto_channels: 16 → 64`。

对照用前序目录 `qm9s_pouter_trace_wE_20260928`（E_true² 加权），
以及 `qm9s_pouter_trace_20260927`（未加权）。三个目录逐键比对，本目录与
`..._wE_20260928` **每组恰好只有一个键不同**（`mto_channels`），其余包括
架构、初值、数据、划分、优化器、调度、早停、评估口径全部相同。

| 组 | 架构 | A 的构造 | 监督 | 初值 |
|---|---|---|---|---|
| G1 | 原 MTO（含 M 旁路） | A = C Cᵀ | LE + Ls + LQ | initial/original.pt |
| G2 | 原 MTO（含 M 旁路） | A = C Cᵀ | Ls | initial/original.pt |
| G3 | P-only 普通 1o 向量 | A = μμᵀ | LE + Ls + LQ | initial/p_outer.pt |
| G4 | P-only 普通 1o 向量 | A = μμᵀ | Ls | initial/p_outer.pt |

改动落在 `model_factory.py`：`PCoupling(c)` / `PDecoder(stats,c)` 参数化，
`PCoupling` 的输出 irreps 由 `{c}x0e + {c}x1o + {c}x2e` 收窄为 `{c}x0e + {c}x1o`
（"CG 只算矢量项"），`PDecoder` 把该 1o 外积得到 A。通道数存为普通属性
`self.c` 而非 buffer，以免进入 `state_dict` 污染参数哈希。

**设置的正确性已由 preflight 验证**：数据文件 sha256 与冻结表逐一相符；
每组恰好一个 config 键不同；`alpha_init` 由 297080.857 重新标定为 330998.984；
`initial/*.pt` 的 `project.0e` 为 (64,128)、`cg.tp` 为 (1835008,)；
`preflight.json` 与 `system_preflight.json` 均 `passed: true`。

> 过程中 preflight 抓到过一次真实缺陷：初值仍按 pinned 的 c=16 生成
> （`size mismatch for mto.project.0e.weight`），已修正后重建。这正是 preflight 的作用。

**训练预算**：`max_epochs=1000, min_epochs=200, early_patience=150`，
约 147 s/epoch，四组并发于 GPU 1/2/4/6。

## 4. 分析：为什么 f R² 上不去

### 4.1 结论：是过拟合，但**不是数据量不够**

G1/G3 同时含 LE 与 Ls，同一次前向、同一 backbone、同一份数据，两个头的泛化差一个数量级：

| 组 | LE 的 val/train | Ls 的 val/train |
|---|---|---|
| c=64 G1 | ×1.26 | **×5.41** |
| c=64 G3 | ×1.15 | **×1.84** |
| c=16 加权 G1 | ×1.52 | **×12.13** |
| c=16 加权 G3 | ×1.34 | **×5.17** |
| c=16 未加权 G1 | ×1.51 | **×10.81** |

E 头用**同一份数据**能泛化到约 1.3×，说明输入里含有可学信号、样本量也够。
差别在**目标**，不在样本数。

### 4.2 "E² 加权把梯度集中到亮态"的假设被否证

实测（`analysis/RESULTS_effective_sample_size.txt`）：

- `N_eff / N = 0.933` —— 加权几乎不改变有效样本数
- top 10% 的样本只占 **14.06%** 的权重
- 逐态权重份额仅 **6.44% – 12.35%**，非常均匀
- **未加权的旧 run 过拟合程度一样**（G1 ×10.81，G2 ×13.11）

加权不是元凶；它最多把 G1 的 gap 从 ×10.81 抬到 ×12.13。

### 4.3 过拟合随训练时间单调恶化

| 组 | ep10 | ep30 | ep60 | 尾部 val 斜率（每轮，投影到 1000 轮） |
|---|---|---|---|---|
| G1 Ls | 0.126→0.148 | 0.065→0.123 | 0.030→0.133 | −0.00031 → 0.229 |
| G2 Ls | 0.144→0.149 | 0.082→0.145 | 0.035→0.141 | +0.00019 → 0.317 |
| G3 Ls | 0.239→0.165 | 0.127→0.153 | 0.083→0.140 | −0.00109 → −0.464 |
| G4 Ls | 0.192→0.175 | 0.144→0.157 | 0.085→0.144 | −0.00016 → −0.008 |

（格式 `train→val`。）val 在 **epoch 17–43 就已触底**，此后 train 继续下降而 val 不再改善。
c=16 的 G1/G3 尾部斜率同样为正（+0.00023 / +0.00020）——两个 campaign 是同一个过拟合形状。

### 4.4 加通道反而**压住**了过拟合

同轮次比较 Ls 的 gap：G1 ×12.13 → ×5.41，G2 ×14.77 → ×5.05，G3 ×5.17 → ×1.84，
G4 ×16.69 → ×1.95。c=64 的 val 曲线整体确实低一档。所以"过拟合源于 16 通道太宽"
是**反的**：窄瓶颈反而过拟合更狠，因为在限容量下它更早开始死记。

### 4.5 对 f R² 的推论

本轮的"没提升"不是"训练不够"。G1 是最干净的对照：c=16 与 c=64 停在**几乎相同的
`best_val`**（0.499315 vs 0.499701），损失水平一致，但 f R² 是 **0.4199 vs 0.4036**——
**等损失、更宽、更晚停，却更差。**

真正的瓶颈是**目标不可从当前表征推出**。逐态 f R² 随态号单调衰减、态 7 为负
（比直接预测均值还差）；负 R² 不是数据量能修的，是特征里缺少该态跃迁偶极的信息。

## 5. 结论

1. **通道数不是 f R² 的瓶颈。** c=16 → 64 使四组均值 0.3694 → 0.3687，实质不变；
   除 G2（+0.027）外均无改善或略降。
2. **假设"H0：16 通道表达不了 A"被否证。**
3. **E² 加权对精度是打平的**（四组均值 0.3661 → 0.3694），不是清晰的改进。
4. **过拟合是真实的，但根治方向不是加数据 / 加容量**，而是改表征或改目标。

## 6. 后续建议

1. **不要再靠加宽通道或加数据量来提 f R²。**
2. 改目标：按态归一化、对暗态加权、或改成排序 / 相对损失。
3. 验证"特征里没有态 7 的信息"这一判断，最便宜的检查是**用真实 E 和真实 tr(A)
   训练一个纯 MLP 去预测 f**，看是否能达到同样的 R²：能则说明是表征问题，不能则说明是目标问题。
4. `min_epochs=200` 在实测下属于**强制超标训练**（val 在 43 轮即平），`best.pt`
   由早停救回，后续轮次不产生收益。
